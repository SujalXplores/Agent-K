# Hosted demo topology

How the demo becomes something a judge can open in a browser, at zero budget.

Everything here is additive — no change to the RAG service, the policy gate, the
eval harness, or `casting.yaml`/`casting.yaml.lock`. The Foundry self-host path
stays exactly as [`SIGNOZ-RUNBOOK.md`](SIGNOZ-RUNBOOK.md) documents it and remains
the reproducible install story; this document is about the *hosted* surface that
sits alongside it.

## The four surfaces

| Surface | Host | Reachable when |
| --- | --- | --- |
| SigNoz dashboard | SigNoz Cloud (30-day trial, no card) | Always |
| Flowdeck Support (`demo/`) | Vercel | Always |
| Agent K landing page (`landing/`) | Vercel | Always |
| RAG service + Postgres + deployer | A machine you control | While you're running the demo |

The split is forced by one hard fact: **the rollback needs the Docker socket.**
The `deployer` sidecar is the sole socket holder — that isolation is what makes
Law 2's sandbox structural rather than a promise — and no free PaaS hands out a
Docker socket. So the Law 2 rollback can only genuinely execute on a machine you
control, and the always-on hosted surfaces are the dashboard and the two web apps.

That is not a gap to hide. State it in the submission: the dashboard and the
customer-facing app are live and public; the rollback is demonstrated on a
controlled host, on video, with the resulting telemetry visible in the same
public dashboard.

## Why SigNoz Cloud for the hosted dashboard

Chosen for speed, since a public link was the requirement and the deadline is
tight:

- 30-day free trial, **no credit card**, which covers the judging window.
- Supports **public dashboard sharing** (Dashboards → Configure → Publish),
  which is the only way a judge sees the dashboard without an account.
- The **SigNoz MCP server works against Cloud**, so Agent K's evidence
  collection is unchanged.
- Zero infrastructure work. Self-hosting SigNoz publicly means a VM with 6–8 GB
  RAM for ClickHouse; the only genuinely free option is Oracle Cloud Always Free
  (4 ARM OCPU / 24 GB), and standing up ARM ClickHouse on the last day of the
  build is the riskiest thing on the table.

Trade-off to know: **after the trial, the deployment is deleted following a
7-day grace period** unless a card is added. Capture screenshots and video
while it is live — do not let the submission depend on a link that expires.

## Wiring the app to SigNoz Cloud

No code change is required. `app/telemetry.py` passes `endpoint=` explicitly but
leaves `headers` unset, so the OTel SDK's `OTEL_EXPORTER_OTLP_HEADERS` env
fallback applies.

**A human has to create the account** — sign up at signoz.io, then note your
region (`us`, `eu`, `in`, `us2`, `eu2`, `in2`), your **ingestion key**, and an
**API key** (Settings → API keys).

```bash
# Telemetry export. Port 443 serves both OTLP/HTTP and OTLP/gRPC on Cloud.
OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.<region>.signoz.cloud:443
OTEL_EXPORTER_OTLP_HEADERS=signoz-ingestion-key=<ingestion-key>

# Agent K's evidence collection + the base for every evidence deep link.
# app/claims.py builds claim links from SIGNOZ_URL, so this must be the UI
# host, not the ingest host.
SIGNOZ_URL=https://<region>.signoz.cloud
SIGNOZ_API_KEY=<api-key>
```

Confirm on first run that spans actually arrive — a wrong ingestion key fails
silently, which is the pitfall flagged throughout this project. If nothing
lands, fall back to the console exporter to prove the app is emitting at all
(`SIGNOZ-RUNBOOK.md`), then fix the transport.

### Importing the dashboard

[`dashboards/agent-k.json`](dashboards/agent-k.json) — 27 widgets across Service
Health, Incident Context, Agent Health, and Action Audit Trail — is generated by
[`scripts/build_dashboard.py`](scripts/build_dashboard.py). Import it via
Dashboards → Import JSON.

Widgets only render once the underlying data exists, so import *after* the app
has served traffic and at least one investigation has run. An empty panel here
means "no data yet", not "broken query" — resist re-authoring queries against an
empty backend.

Then publish it: Dashboards → Configure → **Publish**. Note two documented
limitations — **dashboard variables do not work on public dashboards**, and if
you disable time-range control, viewers see only the default range you pick.

### Evidence links, honestly

`SIGNOZ_URL` pointed at Cloud makes every published claim's evidence link a real
`https://<region>.signoz.cloud/...` URL, and
[`scripts/check_evidence_links.py`](scripts/check_evidence_links.py) can verify
they all resolve using the API key.

But a judge without an account clicking one of those deep links gets a login
page. Only the *published dashboard* is anonymous. So the Law 1 claim to make is
"100% of evidence links resolve, verified by an automated checker against the
live instance" — which is true and checkable — not "any reader can click
through". The same limitation applies to a self-hosted instance, whose UI is
also authenticated.

## Wiring Flowdeck Support

`demo/` needs to reach the RAG service. On Vercel that means the service must be
publicly addressable — a Cloudflare Tunnel (`cloudflared tunnel --url
http://localhost:8000`) in front of the local container is the fastest option
and needs no account for a quick tunnel.

```bash
RAG_API_URL=https://<tunnel-host>
NEXT_PUBLIC_REPORTS_URL=https://<tunnel-host>/report
NEXT_PUBLIC_SIGNOZ_DASHBOARD_URL=<published-dashboard-link>
```

Only `RAG_API_URL` is read server-side; the browser never learns it. The two
`NEXT_PUBLIC_` links are header links and are hidden when unset, so an
unconfigured deploy degrades to a bare help centre rather than dead links.

When the tunnel is down the app still loads and the incident strip stays hidden;
asking a question surfaces the "Could not reach Flowdeck Support" error. That is
the intended failure mode, but it does mean **a hosted Flowdeck link is only
useful while you are running the backend.** If you want the link to survive
unattended, either say so plainly on the page or point judges at the video.

## Demo sequence

1. Flowdeck Support answering well, citations under each reply.
2. Switch on `prompt_regression` via `POST /admin/flags` — the incident strip
   names the scenario and says a rollback is eligible; answers lose grounding.
3. SigNoz: error rate and the SLO burn, the deployment marker.
4. The alert fires the webhook; Agent K investigates.
5. `/report/{id}`: claims with evidence links, the policy verdict, verification.
6. The Law 2 gate approves; the deployer re-creates `rag-app` from the known-good
   tag; Agent K re-queries SigNoz to confirm recovery.
7. Flowdeck Support answering well again.
8. Repeat step 2 with `retrieval_latency` — the strip says a rollback will be
   **denied**, and the gate denies it. The denial is the point: it is the
   evidence that the gate is deciding in code rather than agreeing with the model.
