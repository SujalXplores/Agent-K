# Requirements: Agent K — The Evidence-First Incident Agent

**Defined:** 2026-07-20
**Core Value:** Every conclusion Agent K publishes is traceable to SigNoz evidence, and every action it takes has passed a code-enforced policy gate.

## v1 Requirements

Requirements for the seven-day hackathon build. Each maps to exactly one roadmap phase.

### Foundation (application, telemetry, deployment substrate)

- [ ] **FOUND-01**: A FastAPI RAG support-answering service exists, backed by a single PostgreSQL + pgvector datastore for both support data and vector retrieval
- [ ] **FOUND-02**: The service emits OpenTelemetry traces, metrics, and structured logs to SigNoz, with GenAI semantic-convention attributes (`gen_ai.provider.name`, `gen_ai.usage.input_tokens`/`output_tokens`) on every model call
- [ ] **FOUND-03**: SigNoz is deployed via Foundry from a committed `casting.yaml` with pinned image tags, with `casting.yaml.lock` committed alongside it
- [ ] **FOUND-04**: A clean-machine Foundry rebuild completes in under 15 minutes, verified at least twice before submission
- [ ] **FOUND-05**: A configured cost price-table module computes per-call LLM cost from token counts, since free-tier OpenRouter models report zero billed cost
- [ ] **FOUND-06**: A deployer sidecar exists as the sole holder of Docker Compose control, exposing exactly one authenticated endpoint that rolls back to the previous application version

### Seeded Incidents (fault injection and alerting)

- [ ] **INCD-01**: A prompt-regression incident can be triggered via feature flag, producing an increased failed-answer rate traceable to a deployment marker
- [ ] **INCD-02**: A retry-storm cost-runaway incident can be triggered via configuration flag, producing a cost-SLO breach with flat or near-flat user-facing error rate
- [ ] **INCD-03**: A retrieval-latency incident can be triggered via feature flag, producing a pgvector retrieval delay visible as the dominant span in the trace waterfall, with no deployment-related cause
- [ ] **INCD-04**: A database-pool-exhaustion incident can be triggered via configuration, producing connection-pool errors in logs correlated to failed traces
- [ ] **INCD-05**: SigNoz alerts (separate from the dashboard) fire on SLO/burn-rate breaches for each incident, sized to the demo's compressed incident timeline
- [ ] **INCD-06**: A manual `/demo/trigger` fallback exists so the live demo does not depend on alert webhook timing

### Agent Core (investigation pipeline)

- [ ] **CORE-01**: Agent K is implemented as an explicit Python state machine with discrete stages: collect, hypothesize, validate, policy_gate, act, verify, report — no agent framework
- [ ] **CORE-02**: Only the `hypothesize` stage may call an LLM; `collect`, `validate`, `policy_gate`, `act`, and `verify` contain no LLM client dependency in their decision path
- [ ] **CORE-03**: Agent K connects to the SigNoz MCP server (as a Foundry molding) through a read-only tool allowlist and runs a fixed set of investigation queries per incident
- [ ] **CORE-04**: Every LLM call is instrumented at its call site with GenAI attributes, computed cost, and duration, recorded as Agent K's own telemetry
- [ ] **CORE-05**: Agent K receives incidents via SigNoz alert webhook or the manual trigger, and derives its investigation time window from the alert's start time plus a lookback buffer

### Law 1 — No claim without evidence

- [ ] **LAW1-01**: Every RCA claim is structured with claim text, confidence, and an evidence list, each evidence item carrying its query, time range, link, and relationship to the claim
- [ ] **LAW1-02**: The report renderer strips any claim whose evidence list is empty before publishing — code-enforced, not a prompt instruction
- [ ] **LAW1-03**: Every evidence item includes a SigNoz deep link, generated by a centralized, unit-tested link builder
- [ ] **LAW1-04**: An automated link checker runs during evaluation and confirms every rendered evidence link resolves against the running SigNoz instance (100% target)
- [ ] **LAW1-05**: Agent K creates span links between its investigation spans and the original incident traces

### Law 2 — No action without budget

- [ ] **LAW2-01**: A code-based policy module gates every action on six checks: SLO/burn-rate breach, allowlist membership, cooldown elapsed, confidence threshold, deployment-related cause, and sandbox execution
- [ ] **LAW2-02**: The action allowlist contains exactly one entry: rollback to the previous application version
- [ ] **LAW2-03**: The policy module is a decision table with per-check unit tests against synthetic inputs, written before any seeded incident is run through it
- [ ] **LAW2-04**: Each of the four seeded incidents is engineered to fail (or pass) one specific, named policy check, not tuned post hoc to hit the target split
- [ ] **LAW2-05**: The rollback executor calls the deployer sidecar's single endpoint, waits for recovery, and issues a post-action verification query
- [ ] **LAW2-06**: Every policy decision is emitted as a telemetry span containing the requested action, incident ID, SLO value, threshold, confidence, allowlist result, cooldown result, verdict, and reason
- [ ] **LAW2-07**: When any check fails, Agent K produces an evidence-linked recommendation for a human instead of acting
- [ ] **LAW2-08**: The evaluation run demonstrates exactly two rollback approvals (Incidents 1 and 2) and two rollback denials (Incidents 3 and 4)

### Law 3 — No self without telemetry

- [ ] **LAW3-01**: Agent K records its own LLM call count, token counts, computed cost, and investigation duration
- [ ] **LAW3-02**: Agent K records MCP query count, query failures, repeated queries, hypothesis count, and per-hypothesis confidence
- [ ] **LAW3-03**: A loop breaker hashes each MCP query and halts the investigation on excessive repetition, firing a watchdog alert, marking the investigation incomplete, and escalating with evidence collected so far
- [ ] **LAW3-04**: A cost watchdog halts the investigation when the configured token or cost budget is exceeded, reporting that it could not safely complete within budget
- [ ] **LAW3-05**: Missing LLM usage data is treated as an error to surface, never silently recorded as zero cost
- [ ] **LAW3-06**: Retries are tracked separately from billed/successful calls so they cannot silently corrupt cost accounting or the loop breaker's repetition count

### Reporting and Dashboard

- [ ] **REPT-01**: Each investigation renders an incident report as a versioned Markdown file with evidence links, and the same structured RCA is recorded as SigNoz span events/attributes
- [ ] **REPT-02**: One SigNoz dashboard exists with four sections: service health, incident context, agent health, and action audit trail
- [ ] **REPT-03**: Metric attributes are reviewed for cardinality risk (no unbounded IDs on metric labels)

### Evaluation and Submission

- [ ] **EVAL-01**: Each of the four seeded incidents is run three times, with diagnosis accuracy, cost, and time-to-diagnosis recorded for every run
- [ ] **EVAL-02**: Diagnosis accuracy reaches 4 out of 4 correct top-level diagnoses across the seeded scenarios, reported honestly as "4/4 on four controlled scenarios," never as general production accuracy
- [ ] **EVAL-03**: Zero actions execute outside the policy gate across all runs
- [ ] **EVAL-04**: The two rollback scenarios are compared against a scripted manual baseline
- [ ] **EVAL-05**: Any failed or confusing run is included in the submission blog rather than hidden
- [ ] **EVAL-06**: The submission blog is written from the actual build log and discloses AI-assistant usage (mandatory for the hackathon — non-disclosure is disqualifying)
- [ ] **EVAL-07**: The repository includes `casting.yaml` and `casting.yaml.lock` so judges can re-run Foundry and reproduce the deployment
- [ ] **EVAL-08**: Demo footage and screenshots follow the locked demo script end to end

## v2 Requirements

None. The locked scope explicitly forbids adding capability without first removing an existing one — there is no deferred backlog for this project.

## Out of Scope

Explicitly excluded. Documented to prevent scope creep under time pressure.

| Feature | Reason |
|---------|--------|
| Kubernetes, worker queues, message brokers, extra microservices | Project must stay small enough to finish in seven days and reliable enough to demo live |
| General-purpose chatbot / dashboard with a chat box | Agent K is a workflow with a fixed investigation path, not a conversational surface |
| Unsupervised production remediation | Every action is gated; escalation to a human is the designed outcome for anything the gate cannot approve |
| Expanding the action allowlist beyond rollback | Each additional action dissolves the safety claim the project is built to demonstrate |
| Generic LLM cost tracker as a standalone product | Cost telemetry exists to serve the Law 2 safety policy, not as a product in itself |
| Replacing human incident commanders | Incidents the policy gate cannot safely resolve are escalated by design, not auto-resolved |
| Claiming production-grade accuracy from four scenarios | Evaluation targets are locked at "4/4 on four controlled scenarios"; overstating this undermines the project's own honesty posture |
| Dashboards/alerts-as-code (e.g. Terraform) | Explicitly identified during research as a SigNoz feature knowingly not exercised, not an oversight to fix mid-week |
| Native SigNoz SLO/burn-rate objects as the policy gate's decision path | The policy gate must be pure, testable code; a native SigNoz alert on the same metric still exists for the dashboard story |
| Local embedding models (torch/sentence-transformers) | Would jeopardize the under-15-minute clean-machine rebuild target; OpenRouter's free embeddings endpoint covers this instead |
| Any random additional observability panel or unrelated feature | No feature is added unless an existing feature is removed first — locked scope discipline |
