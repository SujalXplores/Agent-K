## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SigNoz containers → host network | Published container ports (UI 8080, OTLP 4318/4317) cross onto the host's network interfaces |
| foundry install script → developer machine | A remote shell script (`foundry.sh`) is fetched and executed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Information Disclosure / Tampering | SigNoz UI (8080) & OTLP ingest (4318) port bindings | medium | mitigate | Keep bindings localhost/private-network only; SIGNOZ-RUNBOOK.md documents not exposing to a public interface (SigNoz has no UI auth by default). Below the "high" block threshold; local hackathon, non-internet-facing. |
| T-01-03 | Tampering | `curl \| bash` foundryctl install | medium | accept | Official SigNoz install script over HTTPS (signoz.io); documented manual-binary fallback via GitHub releases. Standard, widely-used install path; accepted for a build-time dev tool. |
| T-01-SD | Elevation of Privilege | Docker socket exposure | low | accept | This phase mounts NO docker.sock into any app container (stock SigNoz manifest only). The privilege-isolated deployer sidecar that holds the socket is deliberately deferred to Phase 6. |
</threat_model>
