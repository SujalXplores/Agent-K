<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /ask | Untrusted question text enters the app and flows into the LLM prompt |
| RAG app -> pgvector | Query embedding drives a similarity search over the documents table |
| RAG app -> LLM provider | The constructed prompt + retrieved doc content are sent to the provider with an API key |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-INPUT | Tampering | POST /ask question field | medium | mitigate | AskRequest bounds the question (min_length 1, max_length 2000) via Pydantic; the D-05 system prompt constrains the model to answer only from provided context. No tool-calling or action is taken on the answer in this phase, so prompt-injection blast radius is limited to a bad text answer (Phase 5/6 add the action gates). |
| T-02-DoS | Denial of Service | Unbounded question / retrieval cost | medium | mitigate | Question length capped at 2000 chars; retrieval fixed at top_k=3 (D-03); one LLM call per request. Rate-limit/SLO enforcement is Phase 3's dashboard/alert scope. |
| T-02-KEY | Information Disclosure | LLM API key / prompt content in telemetry | high | mitigate | Reaffirms 02-03: generate() sets only gen_ai model/token attributes via the shared helper; the /ask handler logs lifecycle text ("ask request received", "answer generated"), never the question, prompt, answer, or API key. |
| T-02-SQLI | Tampering | pgvector similarity query | low | mitigate | Retrieval uses SQLAlchemy ORM expressions with a parameter-bound query vector — no string interpolation of user input into SQL. |
| T-02-SC | Tampering | package installs | high | mitigate | No new package installs in this plan; all deps pinned + PyPI-verified in 02-01. |
</threat_model>
