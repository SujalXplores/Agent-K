<objective>
Build the single OpenAI-compatible LLM client module and the shared GenAI-telemetry helper: a provider factory that switches between Groq / Cerebras / Gemini Flash purely by the LLM_PROVIDER env var (RAG-04), and a `generate()` function that wraps each completion in a distinct span carrying stable `gen_ai.*` semantic-convention attributes set through one reusable helper (RAG-03, D-06).

Purpose: This is the generation leg of the three-span `/ask` pipeline (D-07) and the provider-abstraction requirement. The `record_llm_call_attributes` helper is explicitly designed to be reused unchanged by Phase 5's Agent K self-telemetry — a single source of truth for attribute names so dashboard queries built in Phase 3/7 never drift.

Output: `app/observability.py`, `app/llm.py`, and offline (mocked) tests proving provider-switching and span attributes. This plan runs in Wave 1 in parallel with 02-01 — it touches no files that plan touches.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RAG app -> LLM provider | Outbound HTTPS to Groq/Cerebras/Gemini carrying an API key |
| env / secrets -> telemetry | Risk of API keys or raw prompts leaking into spans/logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-KEY | Information Disclosure | LLM API key in env / spans / logs | high | mitigate | Keys are read only from {PROVIDER}_API_KEY env vars (never committed; .env gitignored). record_llm_call_attributes sets NO attribute equal to the api_key, and NO raw prompt/completion content — only model names + token counts. The generation log line records "generation complete" text, not the prompt or key. |
| T-02-04 | Spoofing | Wrong/unintended provider selected | low | mitigate | get_client() defaults to groq and only accepts the three known PROVIDER_CONFIG keys; an unknown LLM_PROVIDER raises a KeyError immediately rather than silently mis-routing. |
| T-02-05 | Denial of Service | Provider errors swallowed, retries hidden | low | accept | This phase does not add retry logic (retry-storm is Phase 3's injected scenario); generate() lets provider errors propagate rather than looping, so no hidden retry cost is introduced here. |
| T-02-SC | Tampering | openai/httpx installs | high | mitigate | Covered by 02-01 (pinned, PyPI-verified in CLAUDE.md). No new package installs originate in this plan. |
</threat_model>
